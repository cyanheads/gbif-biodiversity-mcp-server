# 0.7.4 — 2026-09-20

## Changed

- **Bun engines floor rises to `>=1.4.0`** — required by `@cyanheads/mcp-ts-core` ^0.13.6's mirror driver fix; installs on Bun 1.3 now fail rather than running degraded.
- **Argument rejections return `InvalidParams` (`-32602`)** where they previously returned `ValidationError` (`-32007`); `content[0].text` now closes with a `Recovery:` line and a `(reason invalid_arguments)` suffix. The advertised tool surface — `inputSchema`, `outputSchema`, descriptions, annotations — is byte-identical across the upgrade.
- **`sessionMode: 'stateless'` is now declared in `src/index.ts`** and set actively in `.env.example`; a source run with `MCP_SESSION_MODE` unset resolves `stateless` rather than `auto` → `stateful`. The Dockerfile already pinned `stateless`.
- **Dev-tooling sync** — the skill tree moved from `skills/` to `framework-skills/` (mcp-ts-core #428), and `.github/workflows/codeql.yml` now ships as the repo's one CI workflow.

## Fixed

- **`stripHtml` decoded `&amp;` before the references after it** ([#56](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/56)) — text containing an escaped reference lost a level of escaping: `&amp;lt;` (the four characters `&lt;`) came out as `<`. It now decodes every supported reference in one pass. Reaches `gbif_get_species`, `gbif_get_dataset`, `gbif_search_datasets`, and the `gbif://dataset/{datasetKey}` resource.

## Security

- **CodeQL `js/double-escaping` (high severity)** — the re-decoding described above; see Fixed.

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.12.3` → `^0.13.6`
