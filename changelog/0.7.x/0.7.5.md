# 0.7.5 — 2026-10-08

## Changed

- **Input repairs before validation** (mcp-ts-core 0.13.14; [cyanheads/mcp-ts-core#707](https://github.com/cyanheads/mcp-ts-core/issues/707), [#602](https://github.com/cyanheads/mcp-ts-core/issues/602), [#616](https://github.com/cyanheads/mcp-ts-core/issues/616)) — a string spelling a number is accepted for a number field (`limit: "5"`, `occurrenceKey: "5938027393"`), a lone string for a list (`names: "Parus major"` on `gbif_bulk_match_species`), and `null` at an optional key reads as absent (`rank: null`).
- **Tool errors close with the request ID** (0.13.10; [cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)) — the `content[]` text of a tool error ends with `request <id>`, and tool and resource error `data` carries `requestId`.
- **Argument-rejection hints lead with the field path** (0.13.9; [cyanheads/mcp-ts-core#493](https://github.com/cyanheads/mcp-ts-core/issues/493)) — e.g. `country: country must be an uppercase ISO 3166-1 alpha-2 code …`.
- **`ctx.log` client notifications** (0.13.11; [cyanheads/mcp-ts-core#621](https://github.com/cyanheads/mcp-ts-core/issues/621), [#630](https://github.com/cyanheads/mcp-ts-core/issues/630)) — `notifications/message` honors the `MCP_LOG_LEVEL` floor and masks sensitive fields.
- **MCP SDK transport** (0.13.9, `@modelcontextprotocol/server` ^2.1.0) — a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400` / `-32020`, a JSON-RPC batch over 100 messages is refused, and on stdio stdin EOF aborts in-flight requests.
- **Telemetry config** (0.13.7, 0.13.8) — with `OTEL_ENABLED=true`, `OTEL_EXPORTER_OTLP_ENDPOINT` alone exports traces and metrics, and with no endpoint nothing is exported ([cyanheads/mcp-ts-core#523](https://github.com/cyanheads/mcp-ts-core/issues/523)). OTLP log export is opt-in via `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, and `LOG_TOOL_FAILURE_PAYLOADS` is opt-in ([cyanheads/mcp-ts-core#291](https://github.com/cyanheads/mcp-ts-core/issues/291)); both are documented in `.env.example`.
- **`gbif://species/{taxonKey}` with a non-numeric key** now fails as `-32602` with `data.reason: "invalid_filter"` and the resource's recovery hint, matching `gbif://dataset/{datasetKey}`; it was `ValidationError` (`-32007`) with no `data.reason` or hint. The resource's declared contract named `invalid_filter`, but this path threw an undeclared error.
- **Recovery hints come from each definition's declared error contract** (framework fill, 0.13.10; [cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)) instead of per-call-site `ctx.recoveryFor` forwards. The hint text callers receive is unchanged.
- **Server instructions** — the sentence on a `country`/`publishingCountry` pattern rejection now says it arrives as the generic `-32602` `invalid_arguments` rejection carrying the pattern's message, where it said "with empty structuredContent". The behavior was already in place in 0.7.4; this corrects the text.
- **Docker** — dependencies install in a `deps` stage pinned to `$BUILDPLATFORM` ([cyanheads/mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575)), musl bindings are pruned from the image ([cyanheads/mcp-ts-core#608](https://github.com/cyanheads/mcp-ts-core/issues/608)), the unread `MCP_FORCE_CONSOLE_LOGGING` line is gone (0.13.8), and `oven/bun` moves 1.4.0 → 1.4.2 (0.13.7).
- **`server.json`** ([cyanheads/mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622), 0.13.11) — npm entries use `runtimeHint: "npx"` and drop the `run start:*` package arguments; the streamable-http entry sets `MCP_TRANSPORT_TYPE` to `"value": "http"`, so a registry install of that entry starts HTTP.
- **README tool reference condensed**, keeping each tool's parameters, output fields, and failure reasons; the configuration table gains `LOG_TOOL_FAILURE_PAYLOADS` and a configure-environment install step.
- **Badges and pins** — the README MCP SDK badge reads `^2.2.0` and the Bun badge `v1.4.2`; `CLAUDE.md` and `AGENTS.md` pin framework `^0.13.14` and SDK `^2.2.0`; `packageManager` is `bun@1.4.2`.
- **Packaging** — `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, `coverage/`, and `tests/`; `.gitignore` and `.dockerignore` ignore every `.env*` file (`.gitignore` keeps `.env.example`, `.env.template`, `.env.sample`), and `.dockerignore` adds the MCP registry token files; `package.json` `files` carries `!dist/*.mcpb`.
- **Dev tooling** — `.github/workflows/codeql.yml` analyzes `actions` and `javascript-typescript` in separate jobs; framework skills and scripts are re-synced to 0.13.14.
- **`conflicting_taxon_scope` `when` text** on `gbif_search_species` is capitalized.
