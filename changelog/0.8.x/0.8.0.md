# 0.8.0 — 2026-11-01

## Added

- **Published agent skill `gbif-biodiversity-guide`** (root `skills/`), served over MCP at `skill://gbif-biodiversity-guide/SKILL.md` and shipped with the plugin and `.mcpb` installs — the checks for choosing a region filter, reading counts and trends, reconciling a name list, tracing records to collections and publishers, and concluding a taxon is absent.
- **`gadmGid` filter and `GADM_LEVEL_0_GID` … `GADM_LEVEL_3_GID` facets** on the occurrence tools select records by normalized GADM admin area instead of the verbatim `stateProvince` string. A blank or malformed GID fails as `invalid_filter`; one that matches nothing returns a notice naming the GADM facets. ([#77](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/77))
- **`catalogNumber`, `institutionCode`, `recordedBy`, and `mediaType` filters** and `INSTITUTION_CODE`, `MEDIA_TYPE`, and `RECORDED_BY` facets on the occurrence tools; `gbif_search_occurrences` rows carry `institutionCode` and `catalogNumber`. A `recordedBy` that matches nothing returns a notice pointing at the `RECORDED_BY` facet. ([#78](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/78))
- **`gbif_occurrence_facets` `includeLabels`** adds `counts[].label` (taxon `canonicalName` or dataset `title`) to `KINGDOM_KEY` … `SPECIES_KEY` and `DATASET_KEY` buckets. Opt-in, one request per bucket under a 10 s deadline; unlabeled buckets are counted in `notice`. ([#76](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/76))
- **`publishingOrganizationKey`** on `gbif_get_dataset`, `gbif_search_datasets` rows, and `gbif://dataset/{datasetKey}`, plus `publishingOrganizationTitle` on search rows; the key goes back in as `publishingOrg`. ([#79](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/79))
- **`GBIF_USER_AGENT`** is forwarded through the Claude Code and Codex plugin manifests; root `plugin.json` and `mcp.json` added for Agent Plugins clients.

## Changed

- **22 numeric inputs are now integer-typed** — `taxonKey` (6 tools), `occurrenceKey`, `limit` and `offset` (5 paged tools), `facetLimit`, `facetOffset`, `month` (3 occurrence tools). Fractions, negative `taxonKey`, non-positive `occurrenceKey`, and integers past 2^53−1 now fail as `invalid_arguments` before any request; previously fractions were sent upstream or clamped, and values past 2^53−1 clamped. Over-cap integers still clamp. ([#75](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/75))
- **`gbif_match_species` and `gbif_bulk_match_species` disclose `HIGHERRANK` matches** — a `notice` (single) or per-row `note` (bulk) names the matched rank and taxon and says what `taxonKey` covers — that whole taxon, or its accepted taxon when the fallback taxon is a synonym; GBIF's ambiguity note on a `NONE` surfaces in the `no_match` message and bulk row. `taxonKey` values are unchanged. ([#73](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/73))
- **`gbif_search_species` omits `numOccurrences`** unless GBIF supplies a positive value, and `vernacularName` now comes from the row's English `vernacularNames[]` entries. ([#74](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/74))
- **`.mcpb` bundle cleaner** also strips node-gyp build output and build-only package files, and `.mcpbignore` lists every root dev path.

## Fixed

- **Taxon key `0`** (the *incertae sedis* kingdom) resolves on `gbif_get_species`, `gbif://species/0`, and `gbif_match_species`, and `format()` renders `(0)` after a key. ([#80](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/80))
- **`.mcpb` bundle cleaner** no longer deletes a dependency's own `skills/` code directory (the MCP SDK's `dist/ext/skills/`), whose removal stops the bundle starting.
