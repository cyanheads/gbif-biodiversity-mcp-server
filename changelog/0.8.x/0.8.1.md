# 0.8.1 — 2026-11-12

## Added

- **`checklistKey` on `gbif_match_species` and `gbif_bulk_match_species`** (opt-in) selects the Catalogue of Life eXtended Release, `7ddf754f-d193-4cc9-b351-99906754a03b`, the taxonomy GBIF now maintains in place of the frozen Backbone. Matches return string keys as `checklistTaxonKey` / `checklistMatchedTaxonKey`; `taxonKey` is absent. The `/v2` route is derived from a `GBIF_BASE_URL` ending in `/v1`, and any other base fails as a ConfigurationError. ([#89](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/89))
- **`checklistKey` + `checklistTaxonKey` on the occurrence tools** scope by a Catalogue of Life key (sent upstream as `taxonKey`). `taxonKey` is rejected alongside them, and `KINGDOM_KEY` … `SPECIES_KEY` bucket labels follow `checklistKey`, never key shape. ([#90](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/90))
- **`publishingOrg`, `hasGeospatialIssue`, `typeStatus`, `establishmentMeans`, and `license` filters** on the occurrence tools, and `PUBLISHING_ORG`, `TYPE_STATUS`, `ESTABLISHMENT_MEANS`, and `LICENSE` facets, with `PUBLISHING_ORG` bucket labels. `typeStatus` and `establishmentMeans` are canonicalized against GBIF's vocabularies and match narrower concepts too. ([#86](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/86))
- **`gbif_get_occurrence` and every `gbif_search_occurrences` row** carry `license`, `rightsHolder`, `publishingOrganizationKey`, `acceptedTaxonKey`, `acceptedScientificName`, `recordNumber`, `elevation`, `depth`, `typeStatus`, and `establishmentMeans`; media items carry `rightsHolder`. `gbif_search_occurrences` returns media only with the new `includeMedia`. ([#87](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/87))
- **`gbif_bulk_match_species` entries** are a name string or `{ name, kingdom }`, and `unprocessedNames` returns entries as submitted. A blank entry `kingdom` fails as `invalid_filter`. ([#81](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/81))
- **`acceptedName` on synonym matches** from `gbif_match_species` and `gbif_bulk_match_species`, read from the match response with no extra request. ([#85](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/85))
- **`gbif_occurrence_facets` `includeLabels`** names `GADM_LEVEL_0_GID` … `GADM_LEVEL_3_GID` buckets; a bucket whose lookup returns an empty 200 stays unlabeled. ([#88](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/88))
- **`occurrenceStatus`** on the occurrence tools also takes `DETECTED` and `NOT_DETECTED`, the names GBIF serves on records and `OCCURRENCE_STATUS` buckets, sent and echoed as given. The default stays `PRESENT`.
- **A `scientificName` filter that matches nothing** returns a notice naming the cross-kingdom-homonym reading and the `gbif_match_species` + `kingdom` route.

## Changed

- **`.mcpb` bundle cleaner** also strips `AGENTS.md` and `CLAUDE.md` at any dependency's root and `SKILL.md` files anywhere under `node_modules/`.

## Fixed

- **`gbif_search_species` and `gbif_search_datasets` check `offset + limit` against GBIF's ceilings** (100,000 and 125,000) on the applied limit before any request, failing as `pagination_cap_exceeded` instead of a retried 500 or a blank-filter error. A total past the ceiling draws a notice naming the narrowing routes. ([#84](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/84))
- **A comma-less `decimalLatitude`, `decimalLongitude`, or `coordinateUncertaintyInMeters`** matches only that exact value and now draws a notice on every result, across search, count, and facets. A bare `*` (padded too) fails as `invalid_filter` instead of GBIF's bare 404. ([#83](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/83))
- **`scientificName` descriptions** no longer claim the filter misses synonyms; it resolves them.
- **`gbif_bulk_match_species`** escapes the markdown heading of each name, and its per-name catch rethrows caller cancellation and ConfigurationError instead of recording them as per-name errors.
- **`gbif_occurrence_facets` `includeLabels` under the Catalogue of Life** refuses a non-`/v1` `GBIF_BASE_URL` before the aggregation request.
