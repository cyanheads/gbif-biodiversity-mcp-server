# 0.8.2 — 2026-11-19

## Added

- **`status` on `gbif_search_species`** filters by one or more taxonomic statuses (`ACCEPTED`, `DOUBTFUL`, `SYNONYM`, and four more), OR-ed, and echoes the applied values as a `status` enrichment key. ([#96](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/96))
- **`eventDate`, `geoDistance`, `elevation`, and `depth` filters** on the occurrence tools, and `month` also takes a `"min,max"` range. A bare `*` is refused as `year`'s is, and `geoDistance` must end in a lowercase `km` or `m`. ([#97](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/97))
- **`country`, `basisOfRecord`, `taxonKey`, and `checklistTaxonKey`** on the occurrence tools take an array, OR-ed by GBIF (`taxonKey` and `checklistTaxonKey` up to 100 members); `scope` echoes the array. ([#98](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/98))
- **`gbif_get_occurrence`** returns `informationWithheld`, `dataGeneralizations`, `references`, `occurrenceRemarks`, `habitat`, `samplingProtocol`, `datasetName`, `organismQuantity`, `organismQuantityType`, `dateIdentified`, `isInCluster`, and the `kingdomKey` … `speciesKey` rank keys. Its text fields are escaped in `content[]` and `references` renders as a link. ([#99](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/99))

## Changed

- **`checklistKey` description** states that either value leaves out the records GBIF has not matched to a taxon in that checklist.
- **`scientificName` descriptions** on the occurrence tools state that the name combines with a taxon key as a union, and what an unresolvable name does.

## Fixed

- **`gbif_occurrence_facets` fails as `pagination_cap_exceeded`** past position 1,200,000, before any request (was `invalid_filter`), and past 500,001 on a scope ranking more buckets (was a reasonless `-32001` HTTP 404). The page landing on 500,001 carries a notice, not a continuation, and a continuation that would cross it names the `facetLimit` that lands on it. ([#91](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/91))
- **A bare `*` as `year`** fails as `invalid_filter` naming the open-ended forms; 0.8.1 sent it to GBIF, which answered a `-32001` HTTP 404. ([#93](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/93))
- **`gbif_get_species`, `gbif_get_species_children`, `gbif_get_species_classification`, and `gbif://species/{taxonKey}`** now return `nubKey` and `datasetKey` beside a checklist usage `key`, and no longer describe usage keys as backbone keys; `nubKey` is the key the occurrence tools take, absent where the backbone has no mapping. ([#94](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/94))
- **`gbif_get_dataset` and `gbif://dataset/{datasetKey}`** return `deleted` for a dataset GBIF has deleted, and each coverage's `boundingBox`; a coverage with a box and no description is kept. ([#95](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/95))
- **`gbif_search_species` descriptions** no longer require capitalized `kingdom`, `family`, and `genus` names, and the `gbif_search_publishers` `country` recovery names the forms GBIF parses: alpha-3 codes and its own country names. ([#100](https://github.com/cyanheads/gbif-biodiversity-mcp-server/issues/100))
- **`iucnRedListCategory`** accepts `NE` (Not Evaluated), which 0.8.1 rejected.
- **A `scientificName` GBIF cannot resolve, sent beside a taxon key,** empties the query; the zero's notice now names the name as the cause, where 0.8.1 printed the notice for a name sent alone.
- **`gbif_get_occurrence` and `gbif_search_occurrences`** escape publisher-written text in `content[]`, `eventTime` included, and render an http(s) media URL as a link, as `gbif_get_occurrence` also does for `occurrenceID` and identifier URLs.
- **The country-code rejection** on the occurrence tools and on `gbif_search_datasets` `publishingCountry` states what GBIF does with each form, where 0.8.1 said a country name matches nothing.
- **A `*` range end with whitespace between it and the comma** (`"* ,1990"`) on `year` or `coordinateUncertaintyInMeters` fails as `invalid_filter` naming the corrected form; 0.8.1 sent it to GBIF, which answered a bare 404.
